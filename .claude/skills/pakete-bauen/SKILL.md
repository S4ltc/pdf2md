# Pakete bauen

## Lokal unter Windows

1. Läuft `pdf2md.exe` (`Get-Process pdf2md -ErrorAction SilentlyContinue`)? Dann nicht bauen, sondern den Nutzer bitten, das Programm zu schließen.
2. Bauen: `powershell -ExecutionPolicy Bypass -File build.ps1` (ruft `werkzeuge/bauen.py`, rund 2 Minuten). Das ersetzt nur `dist\pdf2md.exe`; die Nutzerdaten daneben bleiben unberührt.
3. Start-Test: `python werkzeuge/bauen.py starttest` (rund 10 s): startet die exe mit einer Ablage im Temp-Ordner, wartet auf die Versionsanzeige und schließt sie.
4. Paket wie im Release: `python werkzeuge/bauen.py paket NAME TAG` (landet im Projektordner, steht in `.gitignore`).
5. Vor dem Weitergeben: `python werkzeuge/exe_pruefen.py dist/pdf2md.exe --benutzer`.

Fertig, wenn Build und Start-Test ohne Fehler durchlaufen und `exe_pruefen` keinen Benutzernamen findet.

## macOS und Linux

Lokal nicht baubar (kein Mac, kein Linux vorhanden). Änderungen laufen über `bauen.yml` auf GitHub bei jedem Push des Nutzers; Ergebnis und Paketbericht stehen als Annotation am Lauf (Lesen: Skill `veroeffentlichen`, Schritt 7). Systemabhängiges im Programm gehört nach `plattform.py`.

## Hintergrund (aus CLAUDE.md)

- macOS/Linux (Schritt 1 von 3, vorbereitet, nicht von Hand geprueft; der Nutzer hat weder Mac noch Linux): `plattform.py` kapselt alles Systemabhaengige; `plattform.SYSTEM` ist austauschbar, so laufen die Mac-/Linux-Zweige auch in den Windows-Tests. Anzeige: `gui()` = edgechromium / cocoa / qt (PySide6, LGPL; nie PyQt6 = GPL) sonst gtk. Einzelinstanz ausserhalb Windows per `fcntl.flock` auf `.pdf2md.lock` in der Ablage. Ablage als gebaute App auf Mac/Linux im Dokumente-Ordner (App-Paket schreibgeschuetzt). Dateinamen von macOS koennen NFD sein: Namensvergleiche (`namen_plan`) normalisieren auf NFC. `tests.yml` laeuft auf windows/macos/ubuntu; Fehler stehen als Annotation am Check-Run (oeffentlich lesbar: `GET /repos/S4ltc/pdf2md/commits/<sha>/check-runs`, dann `annotations_url`), weil Job-Logs eine Anmeldung brauchen und hier weder gh noch WSL vorhanden sind. Schritt 2: `werkzeuge/bauen.py` (bauen | starttest | paket, gemeinsam fuer alle Systeme; `build.ps1` ruft es auf): Windows eine .exe (onefile), macOS `pdf2md.app` (Bundle-ID io.github.s4ltc.pdf2md, nur ad hoc signiert, Paket per `ditto`), Linux Ordner `pdf2md/` mit PySide6 (LGPL: Ordner statt onefile). Start-Test: Umgebungsvariable `PDF2MD_STARTTEST=<datei>` (kein Nutzer-Schalter), `ui_app._starttest` wartet, bis `#version` die Versionsnummer zeigt (Engine + Seite + Python-Schnittstelle), schreibt JSON und schliesst; Linux unter `xvfb-run`. `bauen.yml` baut bei jedem Push (windows, macos-15 arm64, macos-15-intel, ubuntu-22.04) und schreibt das Ergebnis als Annotation; `release.yml` = Versionspruefung + `bauen.yml` (mit Tests) + Release mit allen Paketen und SHA256SUMS. `plattform.vorbereiten()` schaltet unter Linux die QtWebEngine-Sandbox ab (Ubuntu >= 23.10 sperrt sie; nur lokale Inhalte). Unter Windows lokal geprueft: Build 113 s, Start-Test 9 s, Paket wie bisher. Erster Lauf auf GitHub: alle vier Start-Tests OK (cocoa arm64/Intel, qt, edgechromium). Linux-Paket: mit `--collect-submodules qtpy` 346 MB, mit nur den 7 Qt-Modulen, die pywebview braucht, 323 MB (Windows/macOS je ~82 MB).
